# SPO-32 — TDLP via the import adapter over frozen detections (both tiers)

**Issue:** SPO-32 · **PRD:** [`docs/prds/tracklet-modernization.md`](../prds/tracklet-modernization.md) Phase 3 candidates · **Pre-registration:** [`2026-07-18-phase3-preregistration.md`](2026-07-18-phase3-preregistration.md) §2, §8 · **Comparator:** [`2026-07-18-spo30-comparator-run.md`](2026-07-18-spo30-comparator-run.md) · **Date:** 2026-07-18

**Status: TDLP-bbox scored on both tiers — does NOT meet the pre-registered primary bar (regresses purity and mixed-track on both tiers); documented per the gate. TDLP+ReID: protocol caveat — see §4.**

## Integration path (import adapter, no dependency-tree entry)

TDLP ([Robotmurlock/TDLP](https://github.com/Robotmurlock/TDLP), commit `50344b9`, **MIT**) was
run in a fully isolated `uv` environment under `external-trackers/TDLP` — its code and weights
**never enter this repo's dependency tree** (AC 4). The MIT license and Python 3.11/torch-2.1
stack are self-contained there.

TDLP is an **offline** tracker whose association model consumes per-frame detection features
from a precomputed `ExtraFeatures` store (`tdlp/utils/extra_features.py`), not a live detector.
For the **bbox-only** model that store needs only `{bbox_xywh (normalized), bbox_conf}` per
detection. So the frozen-detections protocol is honoured exactly:

1. **Feed identical frozen detections.** Each held-out sequence's frozen `det.txt`
   (`data/exchange/frozen-detections/<tier>/<seq>/`) — the *same* MixSort-YOLOX (SportsMOT) /
   hosted-incumbent (SoccerNet) detections the comparator and SPO-31 consume — was converted
   into TDLP's per-frame pickle format, with boxes normalized by image dims as TDLP's own
   `feature_extraction.py::postprocess_data` does (`external-trackers/synth_features.py`).
2. **Run TDLP's offline tracker.** Published SportsMOT bbox weights
   (`Robotmurlock/tdlp_sportsmot_bboxes`, HF `model.safetensors`
   sha256 `40126a46…66f1a5`) loaded via the authors' `PyTorchModelHubMixin` path; published
   transform and tracker thresholds from `history/{SportsMOT,SoccerNet}/tdlp_bboxes.yaml`
   (`external-trackers/run_tdlp_frozen.py`). SoccerNet is a **transfer** row — TDLP ships no
   SoccerNet checkpoint, and its own SoccerNet config loads the SportsMOT checkpoint, so we do
   the same.
3. **Import + score.** Each sequence's MOT output was imported via `matchlab-train
   import-tracklets` with a per-sequence `ExternalProvenance` sidecar carrying that sequence's
   frozen `det.txt` sha256; `--frozen-detections` cross-checked the hash, proving TDLP consumed
   our exact frozen detections (AC 2). 2 degenerate off-frame clipped boxes (of ~45k rows) were
   dropped at import. Scored with the full metric stack via a `kind: import` benchmark candidate
   (`comparison_class: matched_data`), baseline = the SPO-30 comparator re-run in the same pass
   (reproduced SPO-30 exactly: SportsMOT HOTA 0.7854 / IDF1 0.8013 / purity 0.9455; SoccerNet
   HOTA 0.5187 / IDF1 0.6052 / purity 0.9257).

Configs: `configs/train/benchmark-phase3-spo32-{sportsmot,soccernet}.yaml`. Imported run dirs:
`data/exchange/external-runs/tdlp-bbox/{tier}/<seq>/` (gitignored).

## Verdict against the pre-registered primary bar

Bar (§2): mixed-track-seconds ≥ 15% relative **reduction** AND purity Δ ≥ +0.01, neither
primary regressing, consistent across both tiers.

| tier | mixed-track | purity | meets bar? |
| --- | ---: | ---: | :--: |
| SportsMOT | **+105%** (worse) | **−0.065** (worse) | no |
| SoccerNet | **+185%** (worse) | **−0.127** (worse) | no |

**TDLP-bbox regresses BOTH primary metrics on BOTH tiers** — it is not promotable under the
gate. It is, however, **better on the leaderboard metrics**: HOTA/IDF1 rise on SportsMOT
(+0.017/+0.047) and IDF1 is non-inferior on SoccerNet.

## Interpretation — HOTA-optimal ≠ purity-optimal

The per-sequence structure is coherent and is the program's thesis made concrete. TDLP is a
learned-association tracker with a 150-frame (6 s) memory; it aggressively reconnects tracklets
across long gaps. Where the comparator **fragments**, TDLP recovers — dramatically:
`v_4r8QL_wglzQ_c001` (crowded, low baseline) HOTA 0.668→0.791, IDF1 0.652→0.810;
`v_G-vNjfx1GGc_c004` IDF1 0.683→0.802. That is why HOTA/IDF1 (association *completeness*) go up.

But the same long-range reconnection **over-connects**, merging identities across gaps and
lowering purity — even on sequences the comparator already solved cleanly:
`v_2QhNRucNC7E_c017` purity 0.995→0.876 / mixed 1.4→32.9 s. TDLP converts fragmentation
(repairable offline) into contamination (must be detected and split) — the exact trade the PRD's
governing objective forbids ("a short pure tracklet beats a longer one that silently switches
players"). The effect is larger on the SoccerNet transfer row, as expected for a SportsMOT-trained
model on broadcast soccer.

This is a clean, decision-relevant result: a SOTA-on-HOTA tracker is **the wrong choice under a
purity objective**. It confirms the value of the program's purity/mixed-track primary axis — the
leaderboard metric would have promoted TDLP; the purity metric correctly rejects it.

## 4. TDLP+ReID variant — protocol caveat (no frozen-detection parity run)

The pre-registration pairs TDLP-bbox with **TDLP+ReID** to measure the *marginal value of
appearance within TDLP* (§7.2). That pairing is **not runnable on our frozen detections**: TDLP's
appearance/keypoint model consumes per-detection `appearance_embeddings` + `keypoints_xyc`
produced by CAMELTrack's KPR-ReID + pose pipeline in a fixed embedding format. Computing those on
*our* frozen detection boxes would require reproducing that exact extraction pipeline; there is no
as-published path that both (a) consumes our frozen boxes and (b) yields TDLP-format appearance
features. Per the issue's stated fallback ("if TDLP cannot consume external detections
as-published, record that as a protocol caveat … do not silently mix the two classes"), the
frozen-detection parity comparison for TDLP+ReID is **recorded as a protocol caveat, not run**.

The marginal-value-of-appearance question is instead answerable via the *as-published* route —
running TDLP-bbox and TDLP+ReID both on CAMELTrack's released SportsMOT `Tracker States`
(identical CAMELTrack detections + appearance + pose for both), which would be a clearly-labeled
`as_published` pair, never mixed with the `matched_data` frozen-detection rows above. That route
is noted for SPO-34 as an optional follow-up; it is a different comparison class and does not gate
promotion. Note the clean marginal-appearance result the gate already has is the SPO-31
BoT-SORT+body-ReID pair, whose appearance mechanism is *ours*.

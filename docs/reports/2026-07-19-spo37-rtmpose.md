(Solution → "Pose: adopt") · **Date:** 2026-07-19 ·

## What shipped: `matchlab_core/pose/rtmpose.py`

`RTMPoseEstimator` — a top-down keypoint front-end (image + person boxes ->
per-box COCO-17 keypoints) that the assembled multi-cue tracker (SPO-42) calls
to attach a pose cue to detections. There is **no `pose` StageKind slot** — pose
is a component feeding the feature assembly, not a pipeline stage, so it's a
plain reusable class (like an embedder), not a `@register`ed stage.

- Runtime: **rtmlib** on **onnxruntime**, no mmcv — far lighter/less fragile
  than the full MMPose+mmcv stack. Lazy-imported and fail-loud (`uv run --with
  rtmlib`), like the detectors.
- `DetectionPose` = `(x, y, score)` per keypoint in source-image coordinates —
  the format the assembly consumes.
- Pure `_to_poses(kpts, scores)` mapping (rtmlib's `(N,K,2)` + `(N,K)` arrays →
  `list[DetectionPose]`), unit-testable without the model.

## Licensing — the decisive nuance (honest per-axis record)

rtmlib/MMPose **code** is Apache-2.0 and the ONNX weight **files** are
redistributed Apache-2.0 — but this is a **false green light**. Every stock
RTMPose *body* checkpoint (including rtmlib's default rtmpose-m) is trained on
**body7**, which includes **AI Challenger (non-commercial)** plus research-only
mixes (MPII/Halpe/CrowdPose/PoseTrack). Even the "COCO-only" RTMPose head uses a
CSPNeXt backbone pretrained on `aic-coco`, so **no stock body checkpoint is
AI-Challenger-free.**

So `RTMPoseEstimator.provenance()` records `training_data` honestly as
**non-shippable**, and the SPO-41 certification gate will **refuse** the stock
weights (tested). This is the correct outcome: the shippable path keeps this
Apache architecture + runtime and **retrains the head on COCO (CC-BY) +
synthetic keypoints** — a cheap retrain, tracked as the SPO-37 follow-up. The
code deliberately does not pretend the Apache weight-file license clears the
training-data axis.

## Acceptance criteria

- ✅ RTMPose produces per-detection keypoints in the feature-assembly format;
  license recorded per axis (code/weights Apache; training-data flagged NC).
- ✅ Runs on an arbitrary video (not benchmark-state-only) — the estimator takes
  raw frames + boxes. **Spot-check** on SoccerNet SNMOT-124 frame 1 with 6 real
  GT player boxes: 6 poses × 17 COCO keypoints; mean keypoint score 0.69–0.79
  for clearly-visible players (17/17 keypoints > 0.5), and correctly low (0.28,
  0/17) for one distant/occluded box — the quality signal the assembly's gate
  can act on.
- ✅ No training required to adopt the runtime — documented; a head **retrain**
  is required only to clear the licensing gate for shipping (follow-up), not to
  run.

## Tests (TDD, 6, green)

`packages/matchlab_core/tests/test_pose_rtmpose.py`: keypoint/score mapping +
empty; fail-loud when rtmlib absent; fail-loud estimate-before-prepare;
code/weights permissive; **training_data flags the non-commercial AI-Challenger
taint** (so SPO-41 refuses stock weights). rtmlib/ONNX inference is exercised by
the spot-check, not the unit suite.

## Follow-up

- **Retrain the RTMPose head on COCO (CC-BY) + synthetic keypoints** to produce

  reuse the same synthetic-data direction as SPO-38. Not required for SPO-42
  integration (which can run stock weights in dev, gated out of shipping).
